# AgentLock 安装与使用

AgentLock 的目标是让当前桌面的 Agent 继续工作，同时遮住物理显示器并限制旁人的普通键鼠操作。Windows x64 本地应用，在原桌面运行，保护不依赖手机持续远控连接。0.1.5 沿用品牌界面，新增通过本人 Windows 登录恢复忘记的保护密码。

## 安装

1. 解压 AgentLock 的 Windows x64 发布包，打开其中的 `AgentLock` 文件夹。
2. 双击 `安装到本机.cmd`。安装位置为 `%LOCALAPPDATA%\Programs\AgentLock`，安装脚本会创建快捷方式，无需管理员权限。
3. 从创建的 AgentLock 快捷方式启动。也可以直接在发布文件夹双击 `AgentLock.exe` 试用。

程序是自包含单文件，不需要另装 .NET SDK。移动便携版本时建议移动整个发布文件夹，以保留安装脚本、说明和实测页面。

本轮测试设备为 Windows build 26200、单显示器、未检测到触屏或笔。其他 Windows 版本、多屏及设备组合需要单独验收。本版本检测到触屏或笔时会拒绝开启保护；保护期间如果系统识别到新增触屏或笔设备，会转入故障降级并尝试 Windows 原生锁屏，GUI Agent 可能暂停。这类设备尚未实际验收。

## 第一次使用

先保存工作，确认知道自己的 Windows 原生登录方式，再进行短时间测试。

1. 点击“设置保护密码”，输入并确认至少 8 个字符的密码。这是 AgentLock 自己的保护密码，与 Windows PIN / 登录密码分别使用。
2. 点击“运行兼容性检查”，在打开的窗口启动检查。屏幕会短暂变黑，检查结束后自动恢复。
3. 查看检查结果。如果基础检查未通过，先按错误提示处理，不开启无人值守保护。
4. 使用自己实际的豆包、GPT / Work 或其他 Agent 做一次测试。推荐双击同目录的 `Agent实测页面.html`，再打开 `给Agent的实测任务.txt`，把其中标明可以复制的任务交给日常使用的 Agent。在它等待的 20 秒内开启保护，然后让它截图、点击三次并输入测试文字。
5. 自己尝试真实鼠标、键盘，确认这些动作不能改变被保护的桌面；随后按 `F12` 呼出密码框，输入保护密码返回。

内置检查验证本机测试窗口、一个截图路径与输入钩子健康状况。**检查通过不能代替豆包、GPT / Work 的实际任务验收，也不能代替真实键鼠测试。**详细步骤见同目录的“验收清单.md”和“兼容性记录.md”。

0.1.5 的 44 项逻辑 / 临时文件测试已通过，新增原生锁定 / 解锁授权、未知状态拒绝与一次性重设回归。本机真实 Windows 登录、自动重设和新密码生效也已通过实际主窗 / 控制流程集成检查，使用独立临时保护凭证。此前基础检查已验证自有窗口的动态 GDI、焦点、合成键鼠及 Unicode；这些结果不等于特定商业 Agent、中文输入法、其他设备或长期任务通过。

离线实测页面应从计数 0、空输入框开始；重复测试先刷新页面。正确结果是两次截图的时钟不同、计数为 3、输入为 `AgentLock 测试通过`，页面显示“测试文字匹配”。让 Agent 使用它平时的桌面截图、鼠标和键盘方式，不能改用读取 HTML、DOM 或后台脚本代替。解锁后保留 Agent 两张截图及任务记录，并记录真实键鼠是否受限。不要向 Agent 提供保护密码。提供这两个测试文件不表示实际 Agent 已通过验收。

## 离开和回来

离开前，让 Agent 任务正常开始，保持默认勾选“离开时隐藏所有屏幕”和“保护期间阻止自动睡眠”，点击“离开并继续工作”。当前桌面的应用和任务保留运行，物理显示器显示黑色遮罩。

开启保护前松开所有按键和鼠标按钮。如果 Agent 正在按住按键或拖动，等这次动作完成再开启。检测到仍有按键 / 按钮按下时，程序会拒绝开启并提示重试；遇到“保护没有开启”提示时，处理并重新开启后再离开。

回来后按 `F12`，松开按键，输入保护密码并点击“解锁”。取消或错误密码会保持保护。连续错误会出现等待，重开应用不会清除未到期等待。

解锁入口统一为 F12；已移除旧版的 `Ctrl+Alt+U` 组合键入口。

若密码框提示“请点击此窗口”，先在框内点击再输入。窗口内实体点击允许其获得焦点，窗口外仍受限；如果 8 秒内仍无法获得键盘焦点，程序会尝试请求 Windows 原生锁屏，是否实际锁定仍需核对。

密码认证期间会暂时阻断 Agent 的合成输入，避免误操作密码框。正在做鼠标或键盘自动化时，应先暂停这次任务；解锁后确认目标应用焦点再继续。纯后台代码任务通常不需要鼠标或键盘，但仍需验证自己的实际运行方式。

关闭主窗口会收起到任务栏右下角。退出程序请使用托盘菜单“退出”；保护中退出需要先认证。

## 忘记密码或出现异常

正常恢复入口是 `F12` 加正确保护密码。**本机已反馈保护中按 `Ctrl+Alt+Del` 无响应，不会显示 Windows 安全界面；不要依赖它作为手动恢复方式。**

忘记保护密码时使用 0.1.5 的恢复按钮：

1. 按 `F12` 呼出密码框，点击“忘记密码”。未开启保护时，也可从“设置保护密码”的验证框进入。
2. 程序请求 Windows 原生锁屏。确认电脑实际进入 Windows 登录界面，不把“正在请求”当作已锁定。
3. 使用自己已配置的 Windows Hello、PIN 或登录密码完成本人登录。系统认证由 Windows 处理，不把这些凭证提供给 Agent 或 AgentLock。
4. 返回桌面后，AgentLock 自动打开“重新设置保护密码”，设置并确认新密码。之后使用新密码进行保护和 F12 解锁。

普通密码框的“取消”仍保持保护，不触发恢复。重设框取消或关闭时保留旧密码，并作废这次重设资格；再次恢复需重新请求并完成 Windows 原生登录。程序没有通过原生状态检查时不授予重设权限；无法确认锁屏 / 解锁时不要离开电脑。本机已实际验证原生登录后的自动重设及新密码生效；重设框取消的真人操作、其他设备和登录配置仍需单独验收。

程序只在确认当前会话实际锁定、随后实际解锁后授予一次重设资格。仅发出锁屏请求、取消密码框或收到未核实的系统通知都不能获得权限；查询失败 / 状态未知保持拒绝授权。原生锁屏会中断 GUI Agent 桌面操作，登录后检查任务与焦点。

程序检测到输入保护或遮罩异常时，仍会自动尝试请求 Windows 原生锁屏；请求不保证实际锁定，故障路径需要验证。真正进入锁屏后，需要实时桌面操作的 Agent 可能暂停。Windows 原生锁屏和管理员操作属于边界，程序不保证在这些状态下维持 GUI Agent 工作。

认证期间程序持续更新屏幕遮罩。密码框的焦点或光标位置无法恢复时，也会请求 Windows 原生锁屏。界面显示“系统锁屏尚未确认”时，请确认实际已经锁定后再离开。主进程失去响应或退出后的持续恢复不会在 30 次请求后停止，而是改为每 10 秒重试；锁屏请求获准与实际锁屏分别记录。这些真实故障路径仍待验收。

本版本用于防止旁人直接使用普通物理键鼠浏览和操作桌面，不是 Windows 原生锁屏的等价替代。管理员、其他同权限软件、合成输入，以及尚未验证的底层输入路径不属于完整防护承诺；强制终止与故障监控反应之间也可能有短暂间隙。

## 日志与兼容性报告

配置和日志保存在 `%LOCALAPPDATA%\AgentLock`。保护密码保存为带随机盐的验证记录，程序不保存 Windows 登录密码。

兼容性报告保存在 `%LOCALAPPDATA%\AgentLock\diagnostics\测试时间`。报告包括 `diagnostic-report.json`、测试截图和基准截图；只代表报告注明的测试范围。分享报告前检查截图是否含个人信息。

应用用带专有标记的键盘与鼠标探针检查过滤器是否响应，健康时会吞掉这些事件。若过滤器失效，可能出现细小鼠标位移；探针不点击、不滚轮，程序随后会尝试原生锁屏。这属于故障边界，不能保证故障期间光标绝对不动。

内置兼容性检查会另外在自己的测试面板和非密码文字框执行鼠标点击与文字输入，用来确认基本操作路径。它不替实际 Agent 执行任务。

## 卸载

先认证并退出 AgentLock，再运行发布包提供的卸载脚本。默认只移除程序和快捷方式，保留保护密码、日志和兼容性报告。请不要把删除密码记录当作正式的解锁方式。

## 开发环境运行与验证

没有使用发布包时，先安装 .NET 10 SDK，再在项目根目录运行源码：

```powershell
dotnet run --project '.\src\AgentLock\AgentLock.csproj' --configuration Release
```

无桌面操作的逻辑检查：

```powershell
dotnet run --project '.\tests\AgentLock.Tests\AgentLock.Tests.csproj' --configuration Release
```

自动测试只使用独立临时凭证目录和内存假恢复后端，不安装全局输入钩子、不发送桌面输入、不实际锁屏、不触碰正式保护密码。
